## Source-backed choices

### Existing tracker: preserve the accounting owner

At [`931c74c`](https://github.com/ryan-brosas/pi-time-tracker/tree/931c74c024a24ae7800a66fe21bccecbf19a945b), inspected locally:

- `project-store.ts:44-107`: SQLite WAL/FULL, workspace mapping, inferred windows and same-ID end extension. This is not a general immutable-event importer.
- `automatic.ts:1-60`: Pi TUI decoding shares a file with the clock; long gaps and backward timestamps have explicit handling. Separate decoding before claiming a Pi-free core.
- `index.ts`: public `ProjectStore`, `AutomaticClock`, `buildAutomaticReport` exports, but root import still reaches the extension.
- `native.ts:1-113`: generated artifact by default; opt-in native numeric file protocol with explicit failure and size/timeout limits.
- `scripts/build-bend.mjs`: uses the pinned compiler plugin at build time to produce a compiler-free module. Compiler-free deployment does not require a native-only rewrite.
- `docs/development.md:169-223`: compiler pin, proof limits and prior Varve decision.

The local tree was clean. No tracker tests were run or source changed during this research.

### ActivityWatch Rust server: adapt separation, not its ledger wholesale

[`aw-transform/src/heartbeat.rs:12-58`](https://github.com/ActivityWatch/aw-server-rust/blob/900852047fb4d1e0cae2b61490014f36cd786a8e/aw-transform/src/heartbeat.rs#L12-L58) merges matching data when the next event falls within pulsetime. Same-file tests exercise merge/no-merge and changed-data cases.

[`aw-datastore/src/datastore.rs:1004-1059`](https://github.com/ActivityWatch/aw-server-rust/blob/900852047fb4d1e0cae2b61490014f36cd786a8e/aw-datastore/src/datastore.rs#L1004-L1059) either inserts or replaces the last heartbeat. This is activity compression, not Workspan's immutable source-event identity or proof of attendance.

**Adapt:** collector/server separation and explicit heartbeat semantics. **Omit:** treating compressed activity as billable time or adopting a second interval-union implementation. Source inspection only, not an ActivityWatch runtime test.

### WakaTime CLI: inspect the failure window, not just “has an offline queue”

[`pkg/offline/offline.go:301-350`](https://github.com/wakatime/wakatime-cli/blob/05f417cf3d23157dd4c551b7ffe4c8c48d18dc3a/pkg/offline/offline.go#L301-L350) commits a queue pop before returning records for delivery. [`heartbeat.go:214-223`](https://github.com/wakatime/wakatime-cli/blob/05f417cf3d23157dd4c551b7ffe4c8c48d18dc3a/pkg/heartbeat/heartbeat.go#L214-L223) formats an identity from event fields. It is not a cryptographic hash or an upstream receipt.

**Adapt:** bounded batching/retry and error classification. **Strengthen for Workspan:** retain until durable acknowledgement, source-generated stable identities and visible conflicts. **Omit:** copying content-bearing heartbeat fields or silently dropping failed evidence. The crash-window risk is source-based reasoning, not a crash experiment performed here.

### Bend upstream versus Tom's fork

The tracker pins Bend 2.0.31 source `1e80ddce5940c9db8fe914f4b13a1f85a0e45b2b`. `monotykamary/bend` is a fork of `bendlang/bend`; its observed default head is `95317d952c8fe5be18ef49f916b2a57250cfb0aa`.

[GitHub comparison](https://github.com/bendlang/bend/compare/95317d952c8fe5be18ef49f916b2a57250cfb0aa...1e80ddce5940c9db8fe914f4b13a1f85a0e45b2b) returned `ahead_by: 34`, `behind_by: 0`. The tracker pin is ahead of that fork head, not vice versa. The user's intended “Tom's version” has not been confirmed.

The pinned [`guide/EFFECTS.md:135-139`](https://github.com/bendlang/bend/blob/1e80ddce5940c9db8fe914f4b13a1f85a0e45b2b/guide/EFFECTS.md#L135-L139) explicitly makes no C ABI promise. Fork [`bend2/main.ts:339-352`](https://github.com/monotykamary/bend/blob/95317d952c8fe5be18ef49f916b2a57250cfb0aa/bend2/main.ts#L339-L352) emits JS, C or a native executable. Current upstream [`main.ts:358-377`](https://github.com/bendlang/bend/blob/22ad9dc8325e963cf931e302c2218e27108046ff/bend2/main.ts#L358-L377) also exposes `.mjs` emission; this newer CLI behavior must not be assumed at the tracker pin.

**Keep:** the existing pin and generated/native policy boundary. **Defer:** upgrades or a different fork until an actual capability need and compatibility probe. **Reject:** a bespoke Rust/C ABI as a v1 dependency. No compiler change or benchmark occurred.

### Revision caveat and useful retrieval pattern

On this deployment, MCP `grep` with a commit SHA returned no files for all eight tested repositories, while the corresponding branch searches and exact-SHA `read_file` calls succeeded. A SHA search miss is therefore not proof that a symbol is absent. Also, the existing tracker reported `isIndexed: false` despite a successful scoped code hit and pinned reads.

Use the verified default branch for discovery, then read the decisive file at the recorded SHA and compare with the current working tree or GitHub head. Do not claim branch metadata alone proves shard freshness. Recheck before implementation because the context tracks moving default branches, not frozen dependency versions.

Useful search-bar examples, not MCP regex strings:

```text
context:workspan file:^README
context:workspan repo:aw-server-rust heartbeat
context:workspan repo:wakatime-cli popHeartbeats
```

For Code Ask, supply an explicit small `repos` list and `visibility: PRIVATE`. Context membership is not permission to send personal activity history or company data to the model.

## Verification limits and next decision

Four bounded Sourcebot investigations informed this design: existing tracker/Varve, delivery semantics, Bend host interfaces, and local Codex origin/history. Decisive source claims were checked rather than accepting their conclusions wholesale. In particular, the current generated Bend module disproves the claim that a runtime compiler is always needed for JS consumption; `notLoaded` is intentional projection, not automatically a gap; and content-derived IDs are not sufficient source-event provenance.

Search/config behavior was exercised. Application tests, native Rust/Bend integration, desktop capability probes, daemon crash recovery and live history import were **not** run. The architecture acceptance ledger specifies those future checks. Confirm which Tom repository was intended before adopting a different backend or compiler fork.
